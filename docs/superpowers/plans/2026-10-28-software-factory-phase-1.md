# Software factory, phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GitLab work item in `react_frontend` labeled `factory_ready` goes through triage, patch, code review loop, precommit-gate, risk check and decision, then merges alone when low risk or waits for a person, and ends verified with a result comment and a Teams card.

**Architecture:** A new GitLab repo `kivvo/software-factory` holds TypeScript scripts, one per step, run as GitLab CI jobs on Hetzner Cloud VMs created per job. Every decision is a pure function with unit tests. Thin adapters talk to GitLab, Teams, Berget (Jev) and the agent CLIs. Agents (`claude -p`, `opencode run`) only edit code and run checks. Scripts make every GitLab write. Run state moves between jobs as a pipeline artifact folder `run/`.

**Tech Stack:** Node 22, TypeScript, pnpm, vitest, `tsx` to run scripts, `zod` for config and payloads, `yaml`, `picomatch`. Claude Code CLI, OpenCode CLI, GitLab REST API v4, Teams Workflows webhook, Berget AI `/v1/systemone`.

**Spec:** `docs/superpowers/specs/2026-10-28-software-factory-design.md` (in agent-config until the factory repo exists; Task 1 copies it into the factory repo).

## Global Constraints

- GitLab: `https://falkenruh.ki-partner-deutschland.de`, self-managed. Use only Free features.
- Factory repo: `kivvo/software-factory`. First target: `kivvo/applications/web/frontend/react_frontend`.
- Never set `ANTHROPIC_API_KEY` in the runner. Claude signs in with `CLAUDE_CODE_OAUTH_TOKEN` (Kirill's seat). Never pass `--bare`.
- Every `claude -p` run: `--output-format stream-json --verbose`, `--settings <factory settings file>`, `--permission-mode dontAsk`, `--permission-prompts none`, `--max-turns <n>`, `--model <id>`.
- Agents get a clean environment. Agents never see `FACTORY_GITLAB_TOKEN`, `TEAMS_WEBHOOK_URL` or the trigger token.
- Jev provider: Berget AI, `BERGET_API_KEY`. Until the key exists, use the mock provider and print that it is the mock. Never fall back to the mock silently.
- Reviewer: DeepSeek through TensorX in OpenCode, `TENSORX_API_KEY`. The reviewer gets no shell and no web tools.
- Labels: `factory_ready`, `factory_running`, `factory_needs_info`, `factory_needs_approval`, `factory_waiting`, `factory_paused`, `factory_blocked`, `factory_done`. At most one state label at a time.
- Every factory comment starts with the line `> *This was generated by AI in the software factory.*`
- Loop limits: 3 code review rounds, 3 precommit-gate rounds.
- At most 2 runs at once per target repo. One run per work item.
- Thresholds (first values): `injection` P(yes) ≥ 0.3 blocks; `clarity` < 6 asks; `risk` confidence < 0.7 bumps one level; Jev 2 passes when `diff_risk` ≤ 4 with confidence ≥ 0.9, `scope` P(yes) ≥ 0.9, `sensitive` P(no) ≥ 0.9.
- Hard rules: protected paths, dependency files, more than 300 changed lines, secret scanner hit, red merge request pipeline. Changing an existing test is allowed.
- Router: trivial/low → `claude-sonnet-5-5`, effort `medium`; medium/high → `claude-opus-5-5`, effort `high`; `effort` score ≥ 8 moves to the second row. Reviewer IDs live in `router.yml`.
- Run record kept as a pipeline artifact for 90 days.
- No deploys. No research preview features. Plain, simple English in comments, docs and cards.

## Review Focus

1. The same label event arrives twice, or someone re-adds `factory_ready` during a run: only one run starts. Test in Task 4.
2. `react_frontend`'s main branch is `master`, not `main`: the factory reads `default_branch` from the API and never assumes `main`. Test in Task 6.
3. Claude hits Kirill's usage limit in the middle of a run: the work item gets `factory_waiting`, the session id is saved, and nothing is labeled blocked. Test in Task 9.
4. A diff renames a file out of a protected path, or holds a binary file: the protected path rule checks both the old and the new path, and binary files count as changed without breaking the line count. Test in Task 7.
5. A work item has an empty description or a very long one: Jev gets the text cut to 8,000 characters, and an empty ticket ends in `factory_needs_info`, not a crash. Test in Task 5.
